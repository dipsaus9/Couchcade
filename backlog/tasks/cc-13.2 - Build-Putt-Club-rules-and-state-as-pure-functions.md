The repo-wide 'pnpm test' has one unrelated pre-existing failure in tooling/budgets: adding a second @couchcade/physics-consuming game (putt-club, alongside strike-night) makes Rollup split the shared Planck/physics code into its own chunk with no single facadeModuleId. tooling/budgets/src/classify.ts attributes any such chunk to the platform total (it only reads facadeModuleId's games/<id>/ folder, not the real import graph), so 'Host platform JS' now measures ~473 KB against its 450 KB budget (baseline before this story: ~427 KB, so ~23 KB of headroom existed and this chunk is ~46 KB). Confirmed by inspecting the real Rollup output that this shared chunk is reachable only via each game's own dynamic import() (never from the eager entry's static imports), so no phone or TV actually downloads it before a physics-using game starts -- this is a classifier attribution bug, not a real regression in what ships eagerly. I deliberately did not fix tooling/budgets from within this story: it's outside CC-13.2's References, and a naive 'exclude anything not statically reachable from the entry' fix is wrong -- it would also stop counting Phaser (a documented, intentional exception: '.size-limit.json' notes explain 'Phaser is folded into the 450 KB host platform JS total' on purpose, even though Phaser is also only reached through a dynamic import chain). A correct fix needs to distinguish 'a dependency only some games share' (should stay out of the platform total, like this one) from 'a dependency every game needs' (Phaser, game-sdk -- meant to count), which the current tool has no signal for. Recommend either a small owner-approved bump to the 'Host platform JS' budget in .size-limit.json, or a follow-up story to teach classify.ts that distinction properly.
