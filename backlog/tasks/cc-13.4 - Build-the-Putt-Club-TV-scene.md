## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. games/putt-club/src/host/layout.ts: per-hole projection (sx/sy from docs/games/putt-club.md
   "TV scene", Projection row), the `green` palette's literal hex (CC-13.5 hasn't landed
   packages/theme/src/scenes/putt-club.ts yet, so these are local constants, not imported),
   cup-radius bucketing from captureRadius, waiting-pip staging line.
2. present.ts: pure PuttClubState -> Presentation (carpet/kerb/hazard polygons, cup+flag, every
   player's ball incl. ghosting, putter+waiting World Pip spots, aim line during `turn`, penalty/
   cap chip, panel text, IN!/BIRDIE!/HOLE IN ONE!/MATCH! callout, scoreboard scores + round).
3. aim-playback.ts: one createPlayback<[yaw,pitch]> for the current putter, delayed by
   host.link?.(id)?.playbackDelayMs ?? AIM_PLAYBACK_DELAY_MS (Target Range's own pattern).
4. overlays.ts: game-local InstructionPanel (Bandeja/Quick Draw pattern) + a small overlay chip
   for the +1/cap number over a ball, positioned with worldToOverlay.
5. world.ts: Phaser Graphics world -- carpet polygon + masked mown stripes, kerb bands, hazards,
   cup/flag, balls with drawPlayerShape markers, World Pips (buildWorldPip) for putter + waiting
   players, aim line. No PNG sprites (none exist yet) and no sound (no asset files to wire) --
   both are CC-13.5's job once it lands; documented as a scoped simplification, not silent gaps.
6. scene.ts: replace the CC-13.2 placeholder. Extends StageScene<PuttClubState> directly (no
   withRewind -- spec's "Fairness" says Putt Club doesn't use it), wires world + overlays +
   scoreboard(round: hole/holeCount) + room code + callout, never mutates state.
7. Tests: games/putt-club/test/host/stage.ts + scene.browser.test.ts (headless boot test, full
   match driven purely by the auto-putt -- no bot AI exists yet, matches the game's own
   deterministic auto-putt-after-deadline mechanism) using createFakeRoom/createPlayers from
   @couchcade/game-sdk/testing; present.test.ts (Node) for callout/panel logic on crafted states.
8. games/putt-club/vitest.config.ts + package.json: add the node/browser/controller project
   split (Bandeja/Strike Night's exact pattern), browser-only deps. CC-13.3 runs concurrently on
   the same two files for its own (jsdom) controller project -- resolve at push-time sync, not by
   picking one side.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Built the Putt Club TV scene: games/putt-club/src/host/ renders PuttClubState at 480x270 with integer scaling (projectionFor in layout.ts maps any hole's own bounds generically, no assumptions about hole layout), extends StageScene using its scoreboard (round: hole/holeCount), room-code and callout overlays plus the game's own bottom instruction panel and a penalty/cap chip. CC-13.5 (assets + the green ScenePalette) hasn't landed yet, so the green, kerbs, cup, flag, balls and aim line are drawn procedurally with Phaser Graphics on the spec's own literal 'Scene palette: green' hex values rather than importing sprites or a palette module that don't exist yet; sound is deferred the same way (no asset files to wire). A headless Chromium boot test (createFakeRoom -- no bot AI exists yet) drives a full 2-player, 9-hole match to 'over' with every hole a calibrated hole-in-one (fast and deterministic, rather than waiting out the auto-putt's deliberately-short cap path) and asserts no console errors; a Node present.test.ts exercises the callout/chip logic (HOLE IN ONE!/BIRDIE!/IN!/MATCH!, +1/cap chips) directly.
