3. e2e/games/bandeja.spec.ts: a bot-plays-a-match test, singles (2 players). Ana (touch) defends
   every ball that reaches her side by tapping the pad's left half (full -60 deg aim) the instant
   the true arrival moment (read off host state) passes; a full-aim shot clears a singles
   opponent's 3.6m reach, so any connect wins the rally. Ben (motion) never swings at all, so his
   side loses every rally either directly or via the CC-23.8 auto-return CPU once his missStreak
   hits 3 -- still losing to Ana's full aim the same way. Timing precision matters (displayLagMs is
   always 0 in E2E, confirmed via research), so the tap is scheduled with the browser's own
   setTimeout inside the phone's page (dispatching a synthetic PointerEvent), not fired from Node,
   to avoid CDP round-trip jitter under load -- verified this fixes flakiness under parallel test
   execution (2-3 workers).
