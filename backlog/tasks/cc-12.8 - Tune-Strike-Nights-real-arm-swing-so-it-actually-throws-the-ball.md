## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Root cause: SWING_RELEASE_WINDOW_MS (300ms) in packages/motion/src/gestures/swing.ts was tuned only against short, fast synthetic traces, and silently dropped a real full-arm bowling swing's natural release timing in Strike Night's own emitOn:"release" mode -- proven directly by the trace generator's own documented default release delay (500ms after peak) emitting zero swings under the old window. Not the CC-5.13 permission/reload issue: bowl.ts has no autonomous fallback-to-touch logic of its own. Fix: raised the release window to 700ms with documented physical reasoning; made the synthetic trace generator's swing arc configurable (armArcDeg, default unchanged so every prior test is untouched); added packages/motion/test/swing/realistic.test.ts with physically-reasoned, documented full-arm-swing fixtures (150-165deg arc, 260-450 deg/s peak, release-timing reasoning from real bowling kinematics) per AC#3's amended wording, since no real device trace exists in this repo/environment (CC-12.9 filed to record one later). bowl.ts needed no code change -- it inherits the new default. All 3 ACs independently verified met (reviewer round 2: pass, 0 scope violations). Verified: pnpm check/test/build/check:deps/check:style all green, plus Strike Night's bot-match e2e (chromium) passes.
