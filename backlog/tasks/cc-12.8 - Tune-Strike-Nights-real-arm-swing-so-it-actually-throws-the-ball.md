Type: deliverable

Reported live during the CC-3.24 owner replay (2026-09-19): "The motion is not letting go of the ball. I need to swipe. I want a full arm range of motion to actually throw the ball." games/strike-night/src/controller/bowl.ts drives createSwingDetector for motion and falls back to createSwingSwipe on timeout/unavailability; CC-12.3's own follow-up already flagged that its thresholds were only ever proven against synthetic traces (createFakeAdapter), never a real phone (games/strike-night/src/controller/bowl.ts, packages/motion/src/gestures/swing.ts). This is the first real-device signal they're wrong: either too strict for a real bowling-style arm swing, or the game is silently falling back to touch before the swing completes.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Root cause (confirmed empirically, not the CC-5.13 permission/reload issue): SWING_RELEASE_WINDOW_MS=300ms in packages/motion/src/gestures/swing.ts was tuned only against short, fast synthetic traces (small ~120deg arc). A real full-arm bowling swing sweeps a much bigger arc and keeps decelerating for longer after its peak, plus needs human reaction time to consciously release the on-screen grip -- easily >300ms. Proven directly: the trace generator's own documented 'natural' default release timing (packages/motion/test/swing/traces.ts gripUpMs = PEAK_MS + 500) already produces zero emitted swings under the old 300ms window in emitOn:'release' mode (Strike Night's exact config in bowl.ts). Fix: raise SWING_RELEASE_WINDOW_MS to 700ms (documented physical reasoning in swing.ts), make the trace generator's fixed 120deg arc configurable (armArcDeg) without changing any existing test's behaviour, and add packages/motion/test/swing/realistic.test.ts with physically-reasoned 'real full-arm swing' fixtures (150-165deg arc, 260-450deg/s peak, realistic release delay) since no recorded real-device trace exists anywhere in the repo (checked packages/motion/test/traces/, spikes/, docs/playtests/). No change needed to bowl.ts itself -- it inherits the new default. Verified: pnpm check/test/build green, plus the Strike Night bot-match e2e (chromium) still passes.
