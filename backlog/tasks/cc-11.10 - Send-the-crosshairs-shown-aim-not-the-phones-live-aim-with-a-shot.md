## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Outcome: a Target Range shot lands where the TV crosshair visibly was at release, not wherever the phone's own live aim happened to be.

Type: deliverable
Branch: CC-11.10/shot-uses-shown-aim

Root cause (found during the CC-3.24 owner replay, 2026-09-19): games/target-range/src/controller/aim.ts's shoot() sends channel.last("aim"), the phone's most recent live-streamed sample. But the TV's displayed crosshair (games/target-range/src/host/aim-playback.ts's createCrosshairPlayback) is a delayed, interpolated/predicted rendering (playbackDelayMs behind), built for the relay path's 4/s budget and reused for the direct link's smoothing. The controller's own comment says the shot should carry "the aim the TV was shown", but the code sends the live value instead, so the two mismatch whenever the aim was still moving at release.
