## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Contract (CC-5.10 follow-up): add optional ControllerProps.motion, a ControllerMotion<TAdapter, TCalibration> union { mode: 'motion', adapter, calibration } | { mode: 'touch' } in packages/game-sdk/src/contract (core cannot import motion, so the types are generic). apps/controller runtime maps the motion session's MotionGame for the running game to it (ready + calibration -> motion, else touch; no motion game -> absent, games treat as touch) and App.vue passes the motion state to GameController. Documented in platform.md.
2. games/target-range/src/controller/: present.ts (pure screen table incl. local drawing/weak/shot states and touch hints), draw.ts (power = clamp(pull/150), 2 decimals), aim.ts (one pose tracker -> createAimDetector or createAimDrag -> createAimSender over one CC-3.6 input stream; recentre at draw for motion; streams only while drawing or dragging the pad; shoot/lower fired with aim at release), AimPad.vue (pad + quiet Centre), clock-sync + haptics, Controller.vue.
3. Tests in games/target-range/test/controller/ (jsdom project like Quick Draw): every state, inputs parsed with inputSchema, touch fallback when motion is absent/touch or switches mid-game, fake adapter for motion, text < 40 chars.
4. Verify: pnpm check, test, build, check:deps, check:style, budgets (per-game chunk <= 25 KB).
